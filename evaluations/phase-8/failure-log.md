# Failure Log

평가 기준은 실행 전에 고정했다. 관찰된 실패, 원인, 수정, 재검증 질문을 시간 순서대로 추가한다.

## F-001 거래소명과 네트워크 평가 충돌

- 수정 전 질문: “업비트에서 거래되는 솔라나의 네트워크를 평가해 줘.”
- 결과: `EXCHANGE_SUPPORT_POLICY`
- 기대: `NETWORK_OR_PROTOCOL_REVIEW`
- 원인: 거래소 키워드가 명시적 네트워크 평가보다 먼저 적용됨

## F-002 스테이블코인 관련 법률 질문 충돌

- 수정 전 질문: “USDC 관련 미국 법률을 설명해 줘.”
- 결과: `STABLECOIN_REVIEW`
- 기대: `LAW_AND_REGULATION` + 보조 `STABLECOIN_REVIEW`
- 원인: 자산명 키워드가 명시적 법률 의도보다 먼저 적용됨

## F-003 한글 음역 법안명

- 수정 전 질문: “클래리티법 알려줘.”
- 결과: `CONCEPT_EXPLANATION`
- 기대: `LAW_AND_REGULATION`
- 원인: `CLARITY Act`만 인식하고 한글 음역+“법” 조합을 인식하지 못함

## F-004 국가명과 기술 비교 충돌

- 수정 전 질문: “한국에서 이더리움과 솔라나의 차이는 뭐야?”
- 결과: `REGULATORY_COMPARISON`
- 기대: `NETWORK_OR_PROTOCOL_REVIEW`
- 원인: 한국 맥락과 비교 표현만으로 규제 비교를 강제함

## F-005 명확한 백서 대상 재질문

- 수정 전 질문: “솔라나 백서 검토해 줘.”
- 결과: `WHITEPAPER_REVIEW`, 불필요한 확인 질문 발생
- 기대: 대상이 명확하므로 바로 시작
- 원인: URL·파일만 식별자로 인정하고 알려진 프로젝트명을 활용하지 않음

수정은 라우팅 우선순위와 식별 판단에 한정한다. 수정 후 기존 질문과 별도 holdout으로 재검증한다.

## 최소 수정과 재검증

- 명시적 법률 의도를 스테이블코인보다 먼저 처리하고 보조 유형을 보존했다.
- 네트워크 평가 의도를 거래소명보다 먼저 처리하되 “이 네트워크”처럼 대상이 없는 질문은 계속 확인한다.
- 규제 비교는 단순 국가명+“비교”가 아니라 법률·규제 의도가 함께 있을 때만 선택한다.
- `클래리티·클래러티` 음역과 명시된 알려진 프로젝트명을 식별한다.
- 국내 토큰증권의 현재 발행 가능성 질문은 RWA 주 유형과 법률 보조 유형을 함께 둔다.
- 수정 전 열 문항을 그대로 다시 실행해 모두 의도한 유형·확인 동작으로 통과했다.
- 별도 holdout 세 문항과 전체 회귀 테스트로 재검증했다.

오탈자 사전을 무한 확장하거나 질문별 예외 함수를 만들지 않았다. 라우터는 보조 수단이며 대화 문맥이 우선한다.
