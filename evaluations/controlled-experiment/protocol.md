# Phase 9 통제 실험 프로토콜

## 동결 설계

- 6개 주제 × 4개 조건 × 5회 반복 = 120개 계획 슬롯
- A: 스킬 없음 + 일반 질문
- B: 스킬 없음 + 상세 질문
- C: 스킬 설치 + 일반 질문
- D: 스킬 설치 + 상세 질문
- A/C와 B/D의 사용자 질문 바이트는 각각 동일하다.
- 각 실행은 새 `codex exec` 세션이며 resume/fork를 사용하지 않는다.
- 기본 실행은 순차 실행이다. 모델, reasoning effort, 웹 검색 허용과 샌드박스 설정을 모든 군에 동일하게 적용한다.
- C/D는 스킬을 설치하지만 사용자 질문에 스킬명을 넣지 않는 intention-to-treat 설계다. 실제 `SKILL.md` 읽기 로그가 없으면 암묵 활성화는 `UNKNOWN`이다.
- 정상 종료된 첫 결과를 본 분석에 사용한다. 실패 재시도는 attempt를 덮어쓰지 않고 추가한다.
- 실행 중 각 슬롯 상태는 `PLANNED`, `RUNNING`, `COMPLETED`, `FAILED`, `BLOCKED` 중 하나다.

## 비교

핵심 비교는 C−B이다. C−A, D−B, D−C, B−A와 상호작용 `(D−C)−(B−A)`도 제시한다. 표본은 조건별 30개로 작으며 보편적 성능을 주장하지 않는다.

## 분리와 눈가림

생성 에이전트는 점수를 매기지 않는다. 생성 종료 후 원본 ID와 무작위 blind ID의 매핑을 별도 파일로 만든다. 평가 에이전트에는 조건과 반복 번호가 없는 blind copy만 제공한다. 자동 보조평가와 인간 검토를 분리하며 인간 검토는 `HUMAN_REVIEW_PENDING`이다.

## 실패·사용량

stdout JSONL, stderr, exit code, 시작·종료 시각을 보존한다. CLI가 토큰 사용량을 노출하면 중복 event를 제거해 집계하고, 노출하지 않으면 `N/A`로 둔다. 실패율의 분모는 계획·시도·성공·채점 슬롯을 각각 명시한다.
