# 이더리움 네트워크 분석 (공식 문서 중심)

**기준일** 2026-11-18 · **깊이** STANDARD · **범위** 글로벌 프로토콜 분석(한국 규제는 질문에 없어 제외)

**근거 등급** 아래 내용은 ethereum.org, EIP-7773(Glamsterdam 메타 EIP)을 조회해 확인한 내용입니다. 원문 발췌 대조(`verify_evidence.py`)는 하지 않았습니다. 그래서 `VERIFIED_FACT`가 아니라 **공식 페이지 기재 내용(조회 확인)**으로 표시합니다. 수수료·사용량·경쟁 네트워크는 공식 문서만으로 확인되지 않아 별도로 표시했습니다. 투자 판단이 아니라 구조 분석입니다.

## 1. 구조: 실행 계층과 합의 계층

- 노드는 **실행 클라이언트**(EVM 실행, 상태·트랜잭션 처리)와 **합의 클라이언트**(PoS 합의, 블록 확정)를 함께 돌립니다. 두 계층은 Engine API로 연결됩니다. 이 API 이름은 공식 페이지 조회 결과에 나오지 않아 제 기존 지식에 근거합니다.
- 밸리데이터는 여기에 검증자 클라이언트까지 포함해 **소프트웨어 3종**을 운영합니다. 공식 문서는 이를 PoS의 단점(복잡성)으로 직접 꼽습니다.

## 2. 지분증명(PoS)

| 항목 | 공식 문서 기재 |
|---|---|
| 참여 | 32 ETH를 예치 컨트랙트에 넣고 활성화 대기열을 거침 |
| 시간 단위 | 슬롯 12초마다 제안자 1명과 무작위 증명 위원회, 에포크는 32슬롯 |
| 확정성 | Casper-FFG. 지분의 2/3 이상이 투표하면 체크포인트가 정당화되고 이전 것이 확정됨 |
| 확정 블록 번복 | 공격자가 전체 스테이킹의 **최소 1/3**을 잃어야 함 |
| 슬래싱 | 단독 슬래싱은 0.1% 미만일 수 있으나 동시 대량 슬래싱은 최대 100%까지 소각 |
| 비활동 누출 | 4에포크 넘게 확정이 안 되면 다수결에 반하는 투표자의 지분을 깎음 |
| 한계 | PoS가 PoW보다 덜 검증됐고 구현이 복잡하다고 문서가 직접 명시 |

- **The Merge**는 2022-09-15에 완료됐고, 에너지 사용을 약 99.95% 줄였다고 문서에 적혀 있습니다.
- 이더리움 재단이 낸 수치이므로 독립 검증된 값이 아닙니다.

## 3. EVM과 개발자 생태계

- **EVM 변화**: Dencun이 임시 저장소(EIP-1153), `MCOPY`, `SELFDESTRUCT` 제한(EIP-6780)을 넣었습니다. Pectra는 BLS12-381 사전컴파일(EIP-2537)을 추가했습니다.
- **개발자 생태계**: 개발자 수·TVL·앱 수는 이번 조회 범위에서 공식 근거를 확인하지 못했습니다(`UNVERIFIED`). 다만 EVM 호환은 L2와 대체 L1이 공유하는 표준이라는 점은 구조적으로 확실합니다.
- **사용 가능한 지표**: ERC-4337 관련 수치(스마트 지갑 2,600만 개 이상, UserOperation 1.7억 건)가 공식 페이지에 있습니다. 기준일이 없는 마케팅성 수치입니다.

## 4. L2와 수수료

- 공식 페이지는 L2를 **"이더리움에 데이터를 저장하는 프로젝트"**로 설명합니다. 데이터를 다른 곳에 두는 체인은 이더리움의 직접 확장이 아닌 독립 네트워크로 구분합니다.
- 안전성은 기술, 컨트랙트 보안, 성숙도에 달려 있고 "공식 L2"는 없다고 명시합니다. 사용자에게는 소액 테스트와 자체 실사를 권합니다.
- **수수료**: 페이지에는 메인넷 평균 약 $0.080, L2 약 $0.0013으로 나옵니다. 출처와 기준일이 없는 수치라 참고만 해야 합니다.
- **데이터 가용성**: 비용 절감은 Dencun의 EIP-4844(블롭, 2024-03-13)로 시작됐습니다. Pectra(EIP-7691)에서 블롭 처리량이 늘었고, Fusaka(2025-12-03)의 PeerDAS로 더 효율적인 데이터 게시가 가능해졌습니다.
- 공식 페이지에는 L2의 스테이지 분류나 L2BEAT 언급이 없습니다. 보안 성숙도 비교는 별도 자료가 필요합니다.
- 로드맵은 샤딩이 "L2가 예상보다 빨리 확장되어" 계획에서 빠졌다고 밝힙니다. **L1은 직접 확장하지 않는다**는 설계 방향입니다.

## 5. 탈중앙화와 보안

- 클라이언트 다양성: 공식 문서는 단일 클라이언트가 33%를 넘으면 위험하다고 봅니다. 33% 초과 시 확정 중단, 2/3 초과 시 잘못된 체인이 확정될 수 있습니다.
- 문서의 스냅샷(2025년 10월 기준)은 다음과 같습니다.
  - 실행 계층: Geth 41%, Nethermind 38%로 **둘 다 33% 초과**.
  - 합의 계층: Lighthouse 42.7%로 **33% 초과**, Prysm 30.9%.
- 같은 페이지에 "Geth 약 85%", "Prysm이 다수"라는 낡은 문장이 남아 있어 **내부 불일치**가 있습니다. 위 수치를 현재값으로 단정하지 말고 clientdiversity.org에서 재확인해야 합니다.
- 검증자 집중도, 스테이킹 비율, 릴레이·빌더 집중은 이번 조회에서 **미확인**입니다.

## 6. ETH의 역할

- 수수료(가스), 스테이킹 담보, 수수료 일부 소각, 검증자 보상 발행이 공식 문서의 역할입니다.
- 공급은 비트코인과 달리 **고정 상한이 없고**, 사용량이 많으면 디플레이션, 적으면 인플레이션이 됩니다.
- Pectra(EIP-7251)로 검증자 최대 유효 잔고가 **2048 ETH**까지 늘었습니다.
- 소각 구조는 해당 페이지에 EIP-1559 이름이 없습니다. 실제 공급 추이는 온체인 데이터가 필요합니다.

## 7. 경쟁 네트워크

이번 조회에서 Solana, 대체 L1, 다른 L2 생태계의 공식 자료는 확인하지 않았습니다. 그래서 **정량 비교는 하지 않습니다**(`UNVERIFIED`). 비교하려면 다음 축으로 각 네트워크의 공식 문서를 같은 기준일에 대조해야 합니다.

- 합의 방식과 확정 시간
- 검증자·클라이언트 수
- 수수료 구조
- 장애 이력
- 개발 언어와 EVM 호환성

설계 철학 차이는 공식 문서에서 읽을 수 있습니다. 이더리움은 L1 노드 요구 사양을 낮게 유지하며 확장은 L2에 맡깁니다.

## 8. 업그레이드: 구현 완료 vs 계획

**구현 완료(메인넷 활성화)**

| 업그레이드 | 일자 | 핵심 |
|---|---|---|
| Beacon Chain | 2020-12-01 | PoS 체인 시작 |
| Paris (Merge) | 2022-09-15 | PoW에서 PoS로 전환 |
| Shapella | 2023-04-12 | 스테이킹 인출 |
| Dencun | 2024-03-13 | 블롭(EIP-4844) |
| Pectra | 2025-05-07 | EIP-7702, 2048 ETH, 블롭 증가 |
| Fusaka | 2025-12-03 | PeerDAS, 가스 한도 6천만 기본값 |

**계획 중(미활성)**

- **Glamsterdam**(공식 로드맵 "2026년 4분기"): ePBS(EIP-7732)와 블록 수준 접근 목록(EIP-7928)이 포함됩니다. 가스 재조정 EIP도 들어갑니다.
  - EIP-7773 기준 18개 EIP가 "Scheduled"입니다.
  - 테스트넷은 Sepolia가 2026-10-06, Hoodi가 2026-10-26로 기재됐습니다. 두 값은 타임스탬프 환산이라 제가 직접 날짜로 바꾼 것입니다.
  - **메인넷 날짜는 미정**입니다. 오늘 기준 메인넷 활성화 근거가 없어 "완료"로 쓰지 않습니다.
  - ethereum.org 이력 페이지는 실행 계층 이름을 Amsterdam, 합의 계층 이름을 Gloas로 적고 EIP는 나열하지 않습니다.
- **Hegotá**(2027): FOCIL(검열 저항)과 프레임 트랜잭션이 목표이고 "범위 미확정"이라고 문서가 밝힙니다.
- **장기 연구(5~10년 가능)**: 양자 내성, 단일 슬롯 확정성, zkEVM, 무상태성. 일정이 없는 연구 과제입니다.

## 9. 계정 추상화

| 항목 | 상태 | 비고 |
|---|---|---|
| ERC-4337 | **구현됨** | EntryPoint가 2023-03-01 메인넷 배포. 프로토콜 변경 없이 동작 |
| EIP-7702 | **구현됨** | Pectra에 포함되어 2025-05-07 활성화. EOA가 스마트컨트랙트 코드를 설정 |
| 프레임 트랜잭션 | **계획** | Hegotá 목표, 범위 미확정 |
| EIP-7701, RIP-7560 | **미확인** | 이번 조회 페이지에 없음 |

- AA 로드맵 페이지가 EIP-7702를 아직 "예정"으로 서술해 이력 페이지와 어긋납니다. 이력 페이지의 활성화 기록을 우선했습니다.
- 개념적으로 AA는 L1 프로토콜에 내장되는 방향이 장기 목표이고 4337은 그 이전 단계입니다. 이 해석은 공식 문서의 명시가 아니라 **근거 있는 추론**입니다.

## 10. 한계와 추가 조사

- 공식 문서 간 불일치: 클라이언트 비율, EIP-7702 상태
- 수치 출처 부재: 수수료 평균, 지갑 수
- 미조회: 거버넌스(All Core Devs), 사고 이력, 스테이킹 집중도, 경쟁 네트워크, 실사용 지표(L2BEAT, 온체인 데이터)
- 코드 구현 상태는 클라이언트 저장소와 스펙 저장소(ethereum/execution-specs, consensus-specs)로 확인하는 것이 가장 확실합니다.
