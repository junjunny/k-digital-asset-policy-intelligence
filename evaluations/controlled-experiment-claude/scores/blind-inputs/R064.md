# 이더리움 네트워크 분석 (공식 문서 중심)

**근거 범위:** 업그레이드 일정과 상태는 ethereum.org의 로드맵·히스토리 페이지를 방금 확인했습니다. 나머지 구조 설명은 ethereum.org와 EIP 문서에 담긴 일반 내용에 기대었고, 이번에 페이지별로 다시 확인하지는 않았습니다. 수수료·TVL·점유율 같은 수치는 시점마다 달라서 일부러 적지 않았습니다. 구체적인 숫자는 L2BEAT, Etherscan, growthepie, beaconcha.in 같은 곳에서 직접 확인하세요.

---

## 1. 두 계층 구조

| | 실행 계층 (EL) | 합의 계층 (CL) |
|---|---|---|
| 역할 | 트랜잭션 실행, EVM, 상태 관리 | 블록 제안·검증, 검증자 관리, 최종성 |
| 클라이언트 | Geth, Nethermind, Besu, Erigon, Reth | Prysm, Lighthouse, Teku, Nimbus, Lodestar |
| 연결 | Engine API로 CL이 EL을 구동 | 동일 |

- 노드 하나는 EL 클라이언트와 CL 클라이언트를 함께 돌립니다.
- 클라이언트를 여러 종류로 나눈 것은 설계 의도입니다. 한 클라이언트에 버그가 나도 네트워크 전체가 멈추지 않게 하려는 장치입니다.
- 다만 특정 클라이언트가 다수 점유율(공식 문서가 말하는 ⅔ 임계 등)을 넘으면 이 이점이 약해집니다.

## 2. 지분증명(PoS)
- **구현됨:** 2022년 9월 15일 The Merge로 채굴이 스테이킹으로 바뀌었습니다. 공식 문서는 에너지 사용이 약 99.95% 줄었다고 설명합니다.
- 검증자는 32 ETH를 예치합니다. 슬롯은 12초, 에폭은 32슬롯이고, Casper FFG로 최종성을 얻습니다. 평균 두 에폭(약 13분)이 걸립니다.
- 부정 행위에는 슬래싱, 비활동에는 inactivity leak이 적용됩니다.
- Shapella(2023.4)로 인출이 가능해졌습니다.
- Pectra(2025.5, EIP-7251)로 검증자 최대 유효 잔고가 2048 ETH까지 늘었습니다.

## 3. EVM과 계정
- EVM은 스택 기반 가상 머신이고 가스로 연산을 계량합니다. 계정은 EOA와 컨트랙트 계정 두 종류입니다.
- 가스 모델은 EIP-1559 이후 base fee(소각)와 priority fee로 나뉩니다.
- 2025년 12월 Fusaka에서 트랜잭션당 가스 상한이 16.7M으로 정해졌고 기본 가스 한도는 60M이 되었습니다.
- Dencun에서 transient storage(EIP-1153)도 들어왔습니다.

## 4. L2와 롤업 중심 확장 전략
- **개념:** L1은 보안과 데이터 가용성을 맡고, 실행은 롤업이 맡습니다.
- **종류:** 옵티미스틱 롤업은 사기 증명을 쓰고, ZK 롤업은 유효성 증명을 씁니다.
- **구현됨:**
  - Dencun(2024.3.13)의 EIP-4844 "blob" 도입으로 L2의 데이터 게시 비용이 크게 내려갔습니다.
  - Pectra에서 blob 목표가 6개(최대 9개)로 늘었습니다.
  - Fusaka의 PeerDAS는 노드가 blob 전체가 아닌 일부만 샘플링하게 해서 데이터 가용성 확장성을 높입니다. 이후 blob을 점진적으로 늘리는 구조도 포함됩니다.
- **한계와 쟁점:**
  - L2마다 유동성과 UX가 파편화됩니다.
  - 일부 L2는 시퀀서가 중앙화돼 있습니다.
  - 증명 시스템과 업그레이드 키의 성숙도가 L2마다 다릅니다. L2BEAT의 "Stages" 구분이 판단 기준이 됩니다.
  - L2 수수료가 내려갈수록 L1 수수료 수입이 줄고 ETH 소각이 감소한다는 비판이 있습니다. 이는 문서가 아니라 커뮤니티 논쟁입니다.

## 5. 탈중앙화와 보안
- **강점:** 검증자 수가 매우 많고, 클라이언트가 다양하며, 가정용 하드웨어로도 노드를 돌릴 수 있게 하는 것을 설계 목표로 둡니다.
- **위험 요소:**
  - 리퀴드 스테이킹과 대형 스테이킹 풀의 집중
  - MEV-Boost 릴레이와 빌더의 집중, 그리고 검열 위험
  - 클라이언트 쏠림
- **계획(미구현):**
  - Glamsterdam의 ePBS(enshrined PBS)
  - 후속 포크의 inclusion list(검열 저항)
  - 장기 과제인 단일 슬롯 최종성과 stateless 클라이언트

## 6. 수수료와 실제 사용
- L1 수수료는 수요에 따라 변하는 시장입니다. blob 수수료는 별도 시장이라 L1 가스와 따로 움직입니다.
- 사용처는 스테이블코인 결제, DeFi, NFT, 토큰화 자산(RWA), L2 앱 등입니다. 구체적 규모는 위 대시보드에서 확인하세요.
- 확장 방향은 L1 가스 한도를 서서히 올리는 것과 L2/blob 용량을 늘리는 것의 병행입니다.

## 7. 개발자 생태계
- **언어:** Solidity와 Vyper가 주류이고, Rust 기반 스택(Reth, Foundry)도 활발합니다.
- **도구:** Foundry, Hardhat, OpenZeppelin, ethers/viem 등
- **표준:** ERC-20/721/1155/4626 등
- **장점:** 가장 큰 개발자 풀, 감사·툴링·유동성 같은 네트워크 효과
- **단점:** 보안 사고 위험(컨트랙트 불변성), L2 간 이식성 문제

## 8. ETH의 역할
- L1 수수료를 내는 가스 토큰입니다.
- 검증자 스테이킹 담보라서 경제적 보안의 기반입니다.
- DeFi와 L2 생태계의 기축 담보 자산이자 결제 자산입니다.
- EIP-1559로 base fee가 소각되고 발행량은 스테이킹 참여에 연동되므로, 순발행은 수요에 따라 인플레이션일 수도 디플레이션일 수도 있습니다.

## 9. 경쟁 네트워크 (일반 지식, 공식 문서 외)
| 네트워크 | 접근 | 이더리움 대비 |
|---|---|---|
| Solana | 단일 고성능 L1, 낮은 수수료 | 처리량과 UX는 유리하지만 하드웨어 요구가 높고 장애 이력이 있음 |
| BNB Chain | EVM 호환, 소수 검증자 | 저렴하고 빠르지만 탈중앙성이 낮음 |
| Avalanche, Sui, Aptos, TON 등 | 각기 다른 합의·실행 모델 | 성능 중심이고 생태계 규모는 작음 |
| Cosmos 앱체인 | 앱별 체인 | 주권은 높지만 보안이 분산됨 |

핵심 비교 축은 모놀리식(성능 우선)과 모듈러·롤업 중심(검증 용이성, 탈중앙성 우선)입니다.

## 10. 업그레이드와 상태 구분

**구현 완료**
| 업그레이드 | 날짜 | 핵심 |
|---|---|---|
| Beacon Chain | 2020.12.1 | PoS 체인 가동 |
| Paris (Merge) | 2022.9.15 | PoW에서 PoS로 전환 |
| Shapella | 2023.4.12 | 스테이킹 인출 |
| Dencun | 2024.3.13 | blob(EIP-4844), transient storage |
| Pectra | 2025.5.7 | EIP-7702, 2048 ETH 검증자, blob 증설 |
| Fusaka | 2025.12.3 | PeerDAS, 가스 상한, 60M 기본 가스 한도 |

**계획 중 (로드맵 기준)**
- **Glamsterdam (Amsterdam + Gloas, 목표 2026년 4분기):** ePBS, block-level access list(병렬 실행·빠른 동기화)
- **Hegotá (Bogotá + Heze, 2027 예상):** fork-choice 강제 inclusion list, 프레임 트랜잭션(계정이 자체 검증 규칙을 정의)
- 두 포크 모두 범위는 확정이 아니라고 문서에 명시돼 있습니다. 히스토리 페이지에는 날짜가 TBD로 되어 있습니다.
- **오늘(2026.11.18) Glamsterdam이 이미 배포됐는지는 이번 조회로 확인하지 못했습니다.** 공식 문서상으로는 아직 "계획" 단계입니다.

**장기 연구 (일정 없음)**
- 포스트 양자 보안, 단일 슬롯 최종성, zkEVM, stateless, danksharding

## 11. 계정 추상화 (AA)
- **구현됨:**
  - ERC-4337: 프로토콜 변경 없이 EntryPoint 컨트랙트, 번들러, 페이마스터로 스마트 계정을 구현합니다. 이미 실사용 중입니다.
  - EIP-7702(Pectra): EOA가 컨트랙트 코드를 위임해 배치 처리, 가스 대납, 권한 제한을 쓸 수 있습니다. 기존 주소를 그대로 씁니다.
- **계획:** Hegotá의 프레임 트랜잭션이 계정별 검증 규칙을 프로토콜 차원에서 지원합니다. 소셜 복구, 지출 한도, 가스 스폰서십, 그리고 포스트 양자 서명으로의 경로가 목적입니다. 이 단계에서 네이티브 AA에 가까워집니다.
- 정리하면 7702는 지금 쓸 수 있는 단기 해법이고, 4337은 생태계 인프라입니다. 프로토콜 네이티브 AA는 아직 계획 단계입니다.

## 종합 평가
- **강점:** 보안과 탈중앙성의 신뢰, 가장 큰 개발자·유동성 생태계, 롤업 중심 확장의 실제 성과(Dencun 이후 L2 비용 하락)
- **약점:** L2 파편화와 UX, 스테이킹·빌더 집중, 변경 속도가 느림
- **관전 포인트:** ePBS와 inclusion list로 검열 저항이 개선되는지, PeerDAS 이후 blob 확장 속도, 프레임 트랜잭션 도입 여부
