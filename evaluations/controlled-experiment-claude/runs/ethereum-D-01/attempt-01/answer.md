# 이더리움 네트워크 분석 (공식 문서 중심)

- **기준일:** 2026-11-18
- **깊이:** STANDARD (여러 주제를 폭넓게 다룬 요약)
- **근거:** ethereum.org 공식 문서 10개 페이지를 조회했습니다. 이 페이지들은 재단·커뮤니티가 관리하는 문서이지 프로토콜 사양 원문이 아닙니다. 표의 `확인됨`은 이 페이지에 그렇게 적혀 있다는 뜻입니다. 사양(EIP, consensus-specs)과 대조하지는 않았습니다.
- **범위 밖:** 경쟁 네트워크, 실사용 지표, 개발자 생태계 통계는 공식 1차 자료를 조회하지 못해 아래에서 `미확인`으로 표시했습니다.

## 1. 구조: 실행 계층과 합의 계층

| 항목 | 내용 | 상태 |
|---|---|---|
| 상태 모델 | 이더리움은 상태 전이 함수 Y(S, T) = S′로 작동하는 분산 상태 머신입니다. 상태는 Merkle Patricia Trie의 루트 해시로 요약됩니다. | 확인됨 |
| 실행 계층 | 실행 클라이언트가 EVM을 구현하고 트랜잭션을 실행해 상태를 갱신합니다. | 확인됨 |
| 합의 계층 | 비콘체인이 PoS 합의를 맡습니다. 실행 계층과 합의 계층은 별도 클라이언트로 함께 운영됩니다. | 확인됨 |
| 합의 계층의 역할 | EVM 문서는 합의 계층의 역할을 직접 설명하지 않았습니다. 여기서는 PoS 문서를 근거로 삼았습니다. | 부분 확인 |

**EVM**
- 1,024개 항목, 256비트 워드의 스택 머신입니다.
- 메모리는 일시적이고, 컨트랙트 스토리지는 영구적입니다. 트랜잭션 범위의 transient storage(TSTORE/TLOAD)도 있습니다.
- 가스는 연산 비용을 계량하고, 스토리지 쓰기가 가장 비쌉니다.
- 구현체는 Yellow Paper를 따릅니다. 독립 구현으로 Py-EVM, evmone, ethereumjs, revm이 있습니다.

## 2. PoS (합의 메커니즘)

문서에 적힌 내용은 다음과 같습니다.

- **검증자:** 32 ETH를 예치하고 실행·합의·검증자 클라이언트 세 가지를 운영합니다. 활성화 대기열이 있습니다.
- **시간 단위:** 슬롯은 12초, 에폭은 32슬롯입니다. 슬롯마다 제안자 1명이 무작위로 뽑히고, 위원회가 투표합니다.
- **최종성:** Casper-FFG를 씁니다. 스테이킹된 ETH의 2/3 이상이 투표하면 체크포인트가 확정됩니다. 확정된 블록을 되돌리려면 공격자가 스테이크의 1/3 이상을 잃어야 합니다.
- **비활성 누수:** 4에폭을 넘게 최종성이 이뤄지지 않으면 다수에 반대 투표하는 검증자의 스테이크가 줄어듭니다.
- **슬래싱:** 한 슬롯에 블록을 여러 개 제안하거나 모순된 증명을 내면 처벌합니다. 첫날 즉시 페널티(최대 0.5 ETH), 18일째 상관 페널티, 36일째 퇴출 순으로 진행됩니다.

PoS 문서는 Pectra의 최대 유효 잔고(EIP-7251) 변경을 다루지 않아, 이 부분은 업그레이드 표에서 별도로 다룹니다.

## 3. 업그레이드: 이미 구현된 것과 계획 중인 것

| 업그레이드 | 일자 | 핵심 내용 | 상태 |
|---|---|---|---|
| The Merge | 2022-09-15 | PoS 전환(EIP-3675) | 구현됨 |
| Shapella | 2023-04-12 | 스테이킹 출금 활성화(EIP-4895) | 구현됨 |
| Dencun | 2024-03-13 | EIP-4844 블롭(proto-danksharding), transient storage | 구현됨 |
| Pectra | 2025-05-07 | EIP-7702(EOA 코드 위임), EIP-7251, EIP-7002, EIP-6110, EIP-7691(블롭 한도) 등 | 구현됨 |
| Fusaka | 2025-12-03 | PeerDAS(EIP-7594), BPO 포크(EIP-7892), 트랜잭션 가스 상한(EIP-7825), 블록 크기 10 MiB(EIP-7934), secp256r1 사전컴파일(EIP-7951), CLZ 옵코드, 기본 가스 한도 60M | 구현됨 |
| Glamsterdam | 로드맵상 2026년 4분기 | enshrined PBS, 블록 단위 접근 목록(BAL) | 개발 중 (메인넷 활성화 여부 미확인) |
| Hegotá | 2027년 예정 | 포크 선택 강제 포함 목록, frame transaction | 계획 (범위 미확정) |

- **날짜 주의:** 로드맵 페이지는 Glamsterdam을 "2026년 4분기"로 적었는데, 오늘이 11월 18일이라 이미 일정이 임박했거나 지연됐을 수 있습니다. history 페이지에는 날짜가 TBD로 되어 있어, 두 공식 페이지의 표기가 다릅니다.
- **BPO 포크:** Fusaka 페이지는 예시 일정만 주고 실제 활성화 여부를 확정하지 않았습니다. 현재 블롭 목표·최대치는 미확인입니다.
- **Fusaka 일부 항목:** 일부 항목은 EIP 번호만 확인했고 클라이언트별 활성 상태는 확인하지 않았습니다.
- **로드맵 항목:** 로드맵 페이지는 이 항목들이 바뀔 수 있고 정확한 시기를 예측하기 어렵다고 명시합니다. 단일 슬롯 최종성은 일정이 없고, 양자내성 보안은 구현까지 5~10년을 보며 우선순위가 낮다고 적혀 있습니다.

## 4. 수수료와 ETH의 역할

**수수료(EIP-1559)**
- 기본 수수료(base fee)는 소각되고, 팁(priority fee)은 검증자에게 갑니다.
- 블록 목표는 가스 한도의 절반이며, 목표를 넘거나 밑돌면 기본 수수료가 블록당 최대 12.5%씩 오르내립니다.
- 블롭 수수료는 별도 시장입니다. Fusaka의 EIP-7918이 블롭 수수료에 최저가를 둡니다. 가스 페이지는 블롭 수수료를 다루지 않았습니다.
- ethereum.org는 L1 단순 전송이 약 $0.0055이고 L2 전송은 보통 $0.01 미만이라고 적었습니다. 이는 페이지 표기이며 시점별 실측 수수료는 따로 확인하지 못했습니다.

**ETH의 역할**
- **수수료 지불:** 가스 결제 수단입니다.
- **스테이킹:** 예치된 ETH가 네트워크를 보호하고 보상을 받습니다.
- **통화 정책:** 공급 상한이 없습니다. 새 ETH가 발행되고 수수료 일부는 소각되므로 사용량이 높으면 디플레이션, 낮으면 인플레이션 쪽으로 기웁니다. 소각된 정확한 수치는 이번에 확인하지 못했습니다.
- **DeFi 담보:** 문서는 ETH 자체가 아니라 WETH(ERC-20)가 Aave 같은 대출 시장에서 담보로 쓰인다고 설명합니다.

## 5. L2 (확장 전략)

- ethereum.org는 이더리움 L1에 데이터를 저장하는 네트워크를 흔히 롤업이라 부르고, 다른 곳에 데이터를 저장하는 프로젝트는 독립 네트워크로 구분한다고 설명합니다.
- OP Mainnet과 Base는 Optimistic Rollup으로 소개됩니다.
- **"공식 이더리움 L2"는 없으며** 설계와 성숙도가 제각각입니다. 안전성은 기반 기술, 컨트랙트 보안, 성숙도에 달려 있다고 경고합니다.
- Fusaka의 PeerDAS는 노드가 블롭 데이터의 약 1/8만 저장하게 해 이론상 최대 8배 블롭 확장을 노립니다. 실제 확장 폭은 BPO 포크 일정에 달려 있습니다.
- 이 페이지에서는 블롭 설명, L2BEAT 단계(Stage) 평가, ZK 롤업 설명을 확인하지 못했습니다. 이 부분은 L2BEAT 같은 외부 자료로 추가 확인이 필요합니다.

## 6. 탈중앙화와 보안

**클라이언트 다양성** (ethereum.org 게시 수치, 실행 계층은 2025-10-26 기준, 합의 계층은 2025년 10월 스냅샷)

| 계층 | 주요 클라이언트 점유율 |
|---|---|
| 실행 | Geth 41%, Nethermind 38%, Besu 16%, Erigon 3%, Reth 2% |
| 합의 | Lighthouse 42.7%, Prysm 30.9%, Teku 13.9%, Nimbus 8.7%, Lodestar 2.7%, Grandine 1.0% |

- 문서가 제시한 위험선은 33%와 66%입니다. 합의 클라이언트가 33%를 넘으면 버그로 최종성이 막힐 수 있고, 66%를 넘으면 잘못된 체인이 최종 확정되어 슬래싱이 발생할 수 있습니다.
- 위 표에서는 Geth, Nethermind, Lighthouse가 33%를 넘습니다.
- **출처 내부 불일치:** 같은 페이지 본문에는 Geth가 "약 85%"라는 문장도 있어 차트(41%)와 충돌합니다. 차트가 더 구체적이라 그것을 썼습니다. 이 수치는 1년 이상 지난 스냅샷이라 현재 값이 아닙니다.
- 검증자 수, 스테이킹 집중도(리퀴드 스테이킹 점유율), 노드 수는 이번에 확인하지 못했습니다.

## 7. 계정 추상화 (AA)

| 방식 | 내용 | 상태 |
|---|---|---|
| ERC-4337 | 프로토콜 변경 없이 UserOperation과 EntryPoint 컨트랙트로 구현합니다. 2023-03-01 메인넷 배포. 페이지는 스마트 월렛 2,600만 개 이상, UserOperation 1억 7천만 건 이상이라고 적었습니다. | 구현됨 |
| EIP-7702 | EOA가 컨트랙트 코드를 위임받는 방식입니다. | history 페이지는 Pectra(2025-05-07)에 포함돼 구현된 것으로 적었습니다. |
| frame transaction | 계정이 자체 유효성 규칙을 정의합니다. | Hegotá에서 검토 중 (미확정) |
| 네이티브 AA(EIP-7701, RIP-7560) | 프로토콜 차원의 AA 방식입니다. | 이번 조회에서 상태 확인 못 함 |

**공식 문서 간 불일치:** AA 로드맵 페이지는 EIP-7702를 아직 "scheduled for May 7, 2025"라고 적고 있습니다. 같은 사이트의 history 페이지는 이를 구현된 것으로 적습니다. AA 페이지가 갱신되지 않은 문구를 남긴 것으로 보이며, 정확한 상태 확인은 EIP 원문과 클라이언트 릴리스 노트로 해야 합니다.

또 Fusaka의 secp256r1 사전컴파일(EIP-7951)은 패스키 기반 서명을 겨냥한 것이어서 AA와 사용자 경험 개선의 연결 고리가 됩니다.

## 8. 미확인 항목과 추가 조사 필요

| 주제 | 이번에 확인 못 한 이유 | 권장 1차 자료 |
|---|---|---|
| 경쟁 네트워크(Solana, 기타 L1 등) | 비교 페이지를 조회하지 않음 | 각 체인의 공식 문서와 독립 데이터 |
| 실사용 지표(TVL, 거래 수, 활성 주소, L2 점유) | 공식 문서가 실시간 수치를 제공하지 않음 | L2BEAT, 블록 탐색기, 데이터 제공자 |
| 개발자 생태계(언어, 도구, 인력 통계) | 개발자 문서 개요만 일부 확인 | ethereum.org 개발자 문서, 독립 개발자 조사 |
| Glamsterdam 메인넷 활성화 여부 | 두 공식 페이지의 표기가 다름 | ethereum/pm(All Core Devs 회의록), EIP 상태 |
| 현재 클라이언트 점유율, 블롭 파라미터 | 게시 스냅샷이 오래됨 | clientdiversity.org, supermajority.info |
| 스테이킹 규모와 집중도 | 조회하지 않음 | beaconcha.in, 스테이킹 대시보드 |

## 9. 종합 평가 (근거 있는 추론)

1. **확인된 사실:** 이더리움은 2022년 PoS로 전환한 이후 2023~2025년에 출금, 블롭, 계정 개선, 데이터 가용성 확장을 순차적으로 출시했습니다.
2. **확인된 사실:** 확장 전략은 L1에서 직접 처리량을 늘리기보다 L2와 블롭 용량 확대에 의존합니다. 그래서 L2마다 보안 모델이 달라진다는 점이 핵심 위험입니다.
3. **추론:** 클라이언트 쏠림(Geth, Nethermind, Lighthouse)은 문서가 제시한 위험선을 넘는 구조적 취약점입니다. 다만 최신 수치는 확인하지 못했습니다.
4. **계획일 뿐인 것:** Glamsterdam 이후의 enshrined PBS, 강제 포함 목록, 단일 슬롯 최종성, 양자내성, 프라이버시는 아직 구현되지 않았거나 일정이 불확정입니다. 로드맵 문서도 변경 가능성을 명시합니다.

이 내용은 정보 제공용이며 투자 권유나 법률 자문이 아닙니다.

원하시면 경쟁 네트워크 비교, 실사용 지표, L2 보안 단계 평가를 L2BEAT 같은 외부 1차 자료로 추가 조사해 이어서 정리하겠습니다. 한국 규제 맥락(국내 거래소 상장, 스테이킹 규제 등)이 필요하면 알려 주세요.
