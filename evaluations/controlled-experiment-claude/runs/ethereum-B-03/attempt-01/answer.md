# 이더리움 네트워크 분석 (공식 문서 중심)

**근거 범위:** 업그레이드 현황은 ethereum.org의 로드맵·히스토리 페이지에서 직접 확인했습니다. 아키텍처 개념(EL/CL, PoS, EVM, L2)은 ethereum.org 개발자 문서의 표준 내용을 제 지식으로 정리했습니다. 수수료, TVL, 노드 수 같은 실시간 수치는 이번에 조회하지 않았으므로 구체적 숫자는 싣지 않았습니다.

## 1. 구조: 실행 계층과 합의 계층

| | 실행 계층(EL) | 합의 계층(CL) |
|---|---|---|
| 역할 | 트랜잭션 실행, EVM 상태 관리, 멤풀 | PoS 합의, 검증자 관리, 포크 선택, 최종성 |
| 클라이언트 예 | Geth, Nethermind, Besu, Erigon, Reth | Prysm, Lighthouse, Teku, Nimbus, Lodestar |
| 연결 | Engine API로 CL이 EL에 "이 페이로드를 실행하라"고 지시 | |

- 노드 운영자는 EL과 CL 클라이언트를 한 쌍으로 돌립니다.
- **클라이언트 다양성**은 설계 원칙입니다. 한 클라이언트의 버그가 네트워크 전체를 멈추지 못하게 하려는 것입니다. 다만 특정 클라이언트(특히 EL의 Geth)에 점유율이 쏠리는 문제는 계속 지적되어 왔습니다.

## 2. 지분증명(PoS)

- **전환:** Beacon Chain(2020.12) 출시 후 The Merge(2022.9.15)에서 PoW를 대체했습니다. 에너지 소비가 대폭 줄었습니다.
- **검증자:** 원래 32 ETH를 예치합니다. Pectra의 EIP-7251로 검증자당 최대 유효잔액이 상향되어 대규모 스테이커의 운영 부담이 줄었습니다.
- **합의 메커니즘:** 슬롯(12초)마다 제안자와 위원회가 선정되고, Casper FFG로 에폭 단위 최종성을 얻습니다.
- **페널티:** 오프라인은 소액 감점이고, 이중 서명 같은 위반은 슬래싱(예치금 삭감)입니다.
- **출금:** Shapella(2023.4)에서 활성화되었습니다. EIP-7002(Pectra)로 실행 계층에서 출금을 촉발할 수도 있습니다.

## 3. EVM과 개발자 생태계

- EVM은 결정론적 스택 기반 VM으로, 가스로 연산을 계량합니다. Solidity와 Vyper가 주 언어이고 Hardhat, Foundry, ethers/viem 같은 도구 체인이 성숙해 있습니다.
- **EVM 호환성**이 가장 큰 해자입니다. 대부분의 L2와 경쟁 체인(BNB, Avalanche C-Chain 등)이 EVM을 채택하거나 호환해서, 개발자와 도구, 감사 인력이 체인 간에 재사용됩니다.
- 표준(ERC-20, 721, 4337 등)은 EIP/ERC 절차로 만들어지고, 이것이 생태계의 상호운용성을 뒷받침합니다.
- 최근 변경 예: Dencun의 일시 저장소(EIP-1153), SELFDESTRUCT 제한(EIP-6780).

## 4. L2와 롤업 중심 확장

- **로드맵의 핵심 전략**입니다. L1은 보안과 결제·데이터 가용성을 맡고, 실행은 롤업이 맡습니다.
- 낙관적 롤업은 사기 증명, ZK 롤업은 유효성 증명으로 L1에 정합성을 보장합니다.
- **구현된 것:**
  - Dencun(2024.3)의 EIP-4844(blob)로 롤업 데이터 비용이 크게 낮아졌습니다.
  - Pectra의 EIP-7691이 blob 처리량을 늘렸습니다.
  - Fusaka(2025.12)의 PeerDAS가 데이터 가용성을 확장했습니다. 검증 노드가 blob 전체가 아니라 샘플만 받으면 되는 방식입니다. blob 파라미터만 바꾸는 포크도 도입되었습니다.
- **한계:** L2 간 유동성·UX 파편화, 시퀀서 중앙화, 업그레이드 키(보안 협의회) 의존이 있습니다. 이는 L2BEAT의 "Stage" 프레임워크로 평가됩니다.

## 5. 탈중앙화와 보안

- **강점:** 다수의 독립 클라이언트와 대규모 검증자 집합, 오랜 무중단 가동 기록이 있습니다.
- **구조적 우려:**
  - 리퀴드 스테이킹(예: Lido)과 거래소로의 지분 집중
  - MEV-Boost 릴레이와 빌더의 집중, 그리고 검열 가능성
  - 노드 운영 하드웨어 요건
- **대응(로드맵):**
  - Glamsterdam의 ePBS는 빌더 관계를 프로토콜 안으로 들여 릴레이 신뢰를 줄입니다.
  - Hegotá의 포크 선택 강제 포함 리스트는 검열 저항을 높입니다.
  - 장기 과제로 무상태성(statelessness)과 양자내성 암호가 있습니다. 로드맵은 일부를 5~10년 뒤로 봅니다.

## 6. 수수료

- 기본 수수료는 EIP-1559(2021)의 베이스 피에 우선 수수료(팁)를 더하는 구조입니다. 베이스 피는 소각됩니다.
- L1 수수료는 수요에 따라 변동합니다. 다만 현재 사용자 대부분의 비용은 L2 수수료이고, L2 수수료는 blob 가격에 크게 좌우됩니다. 그래서 4844와 PeerDAS가 비용 인하 수단입니다.
- L1 자체의 처리량은 가스 한도 상향과 병렬 실행(Glamsterdam 목표)으로 늘리려 합니다.
- 현재 수수료 수준은 시점마다 다르므로 etherscan 가스 트래커나 L2BEAT에서 확인하세요.

## 7. ETH의 역할

1. **가스:** 실행 수수료의 지불 수단
2. **스테이킹 담보:** 보안 예산이자 보상 수취 수단
3. **경제적 담보:** DeFi의 담보와 기축 자산, L2의 수수료 토큰
4. **소각:** EIP-1559 소각과 스테이킹 발행의 균형으로 순발행이 결정됩니다. 소각량이 발행량을 넘으면 순감소(디플레이션)가 되지만, 이는 L1 사용량에 달려 있고 L2로 활동이 이동하면 약해질 수 있습니다.

## 8. 실제 사용

DeFi(대출, DEX, 스테이블코인 결제), NFT, 토큰화 자산(RWA), 스테이블코인 송금, DAO가 대표적입니다. 이용 대부분이 L2로 옮겨 가는 추세라 "이더리움 사용량"은 L1 단독이 아니라 L1+L2로 봐야 합니다. 정확한 TVL과 활성 주소는 DeFiLlama, L2BEAT 등에서 최신 값을 확인하세요.

## 9. 경쟁 네트워크 (구조적 비교)

| 네트워크 | 접근 | 이더리움 대비 |
|---|---|---|
| Solana | 단일 고성능 L1, 병렬 실행 | 낮은 수수료와 높은 처리량, 대신 하드웨어 요건이 높고 모놀리식 |
| BNB Chain | EVM, 소수 검증자 | 저렴하고 빠르지만 탈중앙성이 낮음 |
| Avalanche, Sui, Aptos, Cosmos 등 | 대체 합의·VM, 앱체인 | 각자 다른 트레이드오프, 이더리움의 유동성·개발자 네트워크 효과가 상대적 장점 |

이더리움은 모놀리식 속도 경쟁보다 **보안·중립성·롤업을 통한 모듈형 확장**에 베팅합니다. 이 베팅의 위험은 L2 파편화와 L1 가치 포획이 약해질 가능성입니다.

## 10. 주요 업그레이드: 구현 vs 계획

### ✅ 구현됨 (ethereum.org 히스토리 페이지 기준)
| 업그레이드 | 일자 | 핵심 |
|---|---|---|
| Paris (The Merge) | 2022.9.15 | PoW→PoS (EIP-3675) |
| Shapella | 2023.4.12 | 스테이킹 출금 (EIP-4895) |
| Dencun | 2024.3.13 | blob (EIP-4844), 일시 저장소 |
| Pectra | 2025.5.7 | EIP-7702, 7251, 7002, 7691 |
| Fusaka | 2025.12.3 | PeerDAS, blob 파라미터 전용 포크, 가스 한도 관련 변경 |

### 🛠 계획·개발 중
- **Glamsterdam:** ePBS(EIP-7732), 블록 단위 접근 목록(EIP-7928, 병렬 실행의 기반)이 핵심입니다. ethereum.org는 2026년 4분기를 목표로 적습니다.
  - 검색 결과 중 한 보도는 Sepolia 활성화를 2026.10.6, ethereum.org 페이지는 Hoodi 포크를 2026.10.27로 적었습니다. 오늘이 2026.11.18이라 이미 지난 날짜지만, 실제 진행 여부와 메인넷 일정을 확인하는 공식 발표는 찾지 못했습니다. **메인넷 활성화 여부는 미확인**입니다.
  - 이전 H1 2026 같은 목표가 지연된 이력이 있고, EIP 범위도 확정이 아니라는 표기가 있습니다.
- **Hegotá (2027 목표):** 포크 선택 강제 포함 리스트, 프레임 트랜잭션이 거론되지만 범위는 미확정입니다.
- **장기 연구:** zkEVM으로 L1 검증, 무상태성, 네트워크 수준 프라이버시, 양자내성. 모두 **연구·설계 단계**이며 일정이 보장되지 않습니다. ethereum.org도 "로드맵은 바뀔 수 있고 일정 예측은 어렵다"고 명시합니다.

## 11. 계정 추상화

- **ERC-4337(구현됨, 프로토콜 변경 없이 동작):** UserOperation, 번들러, EntryPoint, 페이마스터(가스 대납)로 스마트 계정을 구현합니다.
- **EIP-7702(Pectra에서 구현됨):** 기존 EOA가 스마트 컨트랙트 코드를 위임받아 배치 실행, 가스 스폰서십 등을 쓸 수 있습니다. 계정을 바꾸지 않고 기능을 얻는 점이 핵심이고, 4337 인프라와도 병행됩니다.
- **프레임 트랜잭션(계획, Hegotá 후보):** 소셜 복구, 지출 한도 등을 프로토콜 네이티브로 만들려는 시도입니다. 아직 범위 미확정입니다.
- **"네이티브 AA"의 완성은 아직 아닙니다.** 현재는 4337+7702 조합으로 실용적 UX가 가능해진 단계입니다.

## 요약 평가

- **확실한 것:** PoS 전환, blob 기반 롤업 비용 절감, 7702로 인한 지갑 UX 개선은 이미 메인넷에 반영되었습니다.
- **진행 중이라 불확실한 것:** Glamsterdam(ePBS, 병렬화), Hegotá(검열 저항, 프레임 트랜잭션)는 일정이 지연되어 왔고 범위도 유동적입니다.
- **미해결 위험:** 스테이킹·빌더 집중, L2 파편화와 중앙화, 경쟁 L1 대비 UX·처리량.

최신 Glamsterdam 상태와 지표는 [ethereum.org 로드맵](https://ethereum.org/en/roadmap/)과 forkcast, L2BEAT에서 한 번 더 확인하시길 권합니다.
